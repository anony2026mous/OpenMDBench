## 1. 想解决的问题

现行的 MD-AD-002 有四个结构性毛病（详见 `doc/engine_defects_for_engineering.md` 与本目录同级的分析文档）：

1. **胜负由"自动近防炮"决定，而不是由策略决定**：红方 15 架自杀无人机 vs 蓝方 3 架拦截机 × 2 发导弹，蓝方数学上无法阻止破防；唯一能救蓝方的是 24 发自动近防炮。
2. **得分是"隐形方框"**：`zone.denial`（±8 km 方框）+ "≥3 架进框"二值终局，一旦触发就抹平前面所有努力，方法之间拉不开差距（实测 INT-003 三档 × 三方法结果完全相同）。
3. **没有可争夺的实体目标**：红方只能"进框"，不能打具体目标，因此没有"先打哪个、投多少架"的取舍。
4. **敌我不同构**：红方无人机没有传感器、没有武器、且由脚本航路驱动 → 只测了蓝方的策略。

本场景按新方案重建：**敌我同构的巡飞弹无人机 + 岛上/水上设施作为计分对象 + 移除近防炮保留岸基雷达**。

## 3. 计分与胜负（初步）

- **终局规则**（引擎侧动态判定，用 `count` 算子对 `tag=facility` 的实体计数）：
  - `rule.facilities-lost`：4 个设施全被摧毁 → 红方成功（优先级 100，终局）；
  - `rule.defence-success`：撑到 t=1800 → 蓝方成功（优先级 50，终局）。
- **分级分**（设施攻防状态 0–4）由**评测侧**按裁判真值计算。
  ⚠️ 引擎 V2 的评分块读取的是**静态 value**（引擎侧没有动态计分插件，实测 MD-AD-002 的三个指标整局不变，总分恒为 0.4），因此本场景把 `score.facility-integrity` 显式声明为 **N/A（available: false, value: null）**，避免有人误把静态常数当成绩。

## 4. 与既有场景的差异（相对 MD-AD-002）

| 项 | MD-AD-002 | MD-AD-006 |
|---|---|---|
| 计分对象 | ±8 km 隐形方框 + 破防二值终局 | 4 个实体设施（3 岛上 + 1 水上）的攻防状态 |
| 红方无人机 | 无传感器、无武器、脚本航路 | 同构载荷（雷达 + 光电 + 2 发巡飞弹） |
| 近防炮 | 2 站点 × 12 发自动开火（主导胜负） | **移除**（保留岸基预警雷达） |
| 水面 | 2 艘纯传感器哨舰，不参与胜负 | 蓝方 3 艘武装无人船（近程水上导弹）+ 红方 5 艘自爆船 |
| 气象 | 环境资源没有标准修正键 → **完全无效** | 本 Catalog 的环境**带标准修正键**（雨雾：雷达距离 ×0.7、探测概率 ×0.8） |
| 交战规则 | 只声明了蓝方→红方 | **双向**（红方也能开火） |
| 碰撞毁伤引用 | 借用 `effect.ciws-hit` | 新增中性命名的 `effect.collision-impact` |

## 5. 已知的待办（初步构建的边界）

1. **红方目前仍是脚本航路**（`agents.yaml` 的 `objective_m` 是岛礁中心，`pattern: direct`），不是策略驱动；"无人机打 3 个设施、自爆船打码头"的分工**尚未在行为层实现**——需要红方接入策略接口，或让脚本按目标分配航路。
2. **脚本驱动的速度是单一值**（`attack.speed_mps: 43.0`，适用于无人机）；无人船最大 12.9 m/s，需要给红方驱动加"按平台/域分别设速"的逻辑（评测侧代码改动）。
3. **分级分在评测侧计算**（引擎不给动态分），需要把"设施存活/受损/摧毁 → 0–4 分"的映射写进评测脚本。
4. **资源标定未做**：12 架无人机 × 2 发 vs 9 架无人机 × 2 发 + 3 艘无人船 × 2 发，谁先耗尽、能否守住 4 个设施，需要跑规则组基线来定标。
5. **未接规则组/LLM 组基线**：需要确认 `run_episode.py` 的防御方构造能识别本场景的 `agents.yaml`（两条武器策略：无人机对空、无人船对海）。
6. **潜艇码头是"水面静态结构"**：如果希望在视觉上更接近"码头"，需要一个新的可视化外形资源（当前复用了无人船的外形引用占位）。
