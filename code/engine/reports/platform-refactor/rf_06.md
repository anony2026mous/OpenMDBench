## 交付能力

- CombatSystem 仅从 Resolved、Catalog、ModelRegistry 与权威 World 构造；authority、contact、ROE、capability、lifecycle、ammo、energy、cooldown 和 target domain 按稳定顺序裁决。
- request fingerprint ledger 在任何抽样或写入前处理幂等与冲突；跨 checkpoint、跨 tick 重放保持零副作用。
- Registry 每次创建 session-local 可执行 HitModel；每发拥有独立确定性子流，以及 model/input/probability/sample/hit receipt；模型 continuation state 进入 checkpoint。
- Engagement、Effect、Damage、ammo、energy、cooldown、RNG、ledger、entity、component、capability、controller 与 adapter state 在同一 World 事务中提交或回滚。
- RF-05 collision/environment 与 weapon 使用唯一 canonical `DamageIntentV2`；Effect→Damage exact chain、单位、模型与 artifact evidence 全部 fail closed。
- 组件毁伤使用显式 profile/magnitude，支持 partial、disabled、destroyed 与共享 capability 重算，不由场景代码直接写 health。
- World 默认无 contact/ROE；仅接受显式 typed 安装，并将证据纳入 checkpoint、完整性与恢复。
- `WorldTickInputV2` 使用 typed entity commands，由 World 内部真实 native adapter 逐 tick 执行；统一编排 lifecycle、dynamics/motion、boundary/collision、typed events、damage 与 cooldown。
- tick pipeline 支持 spawn/despawn topology 重建、延迟 cleanup、五阶段 receipt、operation ledger、checkpoint N+M 与任一阶段故障的整批回滚。
- typed weather、jamming、message、component suppression、mission marker、zone activation 与 apply-effect 均保存 owner state、完整 payload 及前后状态 hash。
- 空间毁伤政策由 Scenario 显式声明，进入 Resolved/hash/checkpoint；支持 constant、scaled relative speed、relative kinetic energy，并使用 response 前 impact evidence。
- World policy 资源从 Effect 根递归展开完整 Catalog dependency closure；零实体/零武器场景也能拥有 session-local World DamageModel inventory。
