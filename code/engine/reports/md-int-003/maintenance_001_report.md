# MD3-MAINT-001：MD-INT-003 维护修复报告

状态：DONE
基线：`9429392666df2928fc61934e49923733deeacb1d`（`refactor`）

## 范围

本次只处理以下三项已复现问题：USV MMG 推进不足、USV 开火能量单位不一致、仿真时间到期未返回终局。未修改场景 ID、阵营或实体 ID 的通用逻辑；未修改依赖、任务时长和源场景参数。

## 复现与根因

1. 18 m/s 导航指令下，攻击 USV 修复前首 tick 仅约 `0.0024 m/s`，20 tick 后约 `0.045 m/s`。原始 `max_nps: 5` 是 Sim2Sea L7 代理模型无法建立有效推进的直接原因。
2. 运行时 `Entity.state.energy` 的合法范围是 `0..1`；武器配置却以 `15000 J` 参与同一比较，因此开火合法性始终失败。
3. 第 1,500 个物理区间结束后，世界已完成到 tick 1,500，但任务判定仍读取 tick 1,499；时间规则漏判，`terminal_result` 为 `null`。

## 修复

- 将 MMG 的通用、安全上限扩展为 `240 rps / 18 m/s`，并由每个动力学资源的数据声明注入 worker。MD-INT-003 两类 USV 分别声明 `200 rps / 15 m/s`、`240 rps / 18 m/s`。
- 保持能量运行态为无量纲比例：将档案中的待机/运动消耗率以及防御 USV 的单发能耗按 `capacity_j` 换算；任务资源事实的能量单位同步为 `1`。
- 在每个物理区间完成后先推进世界 tick，再计算任务和评分；Gymnasium 接口将 `timeout` 映射为 `terminated=False, truncated=True`，并在 `info.terminal_result` 返回终局载荷。

## 验证

- 公开导航动作连续运行 20 tick：攻击 USV 位移超过 `100 m`、速度超过 `10 m/s`。
- 合法开火会扣除比例能量和弹药；能量不足的开火仍不产生资源/RNG 副作用。
- 两 tick 的真实场景结构副本中，第二个物理区间返回 `timeout`；从第一个 tick checkpoint 恢复后，终局结果完全一致。
- MD-INT-003 T2/T3 回归：`78 passed in 184.23s`；通用任务/动力学/会话回归：`143 passed in 18.36s`。
- 5 个改动生产模块的 mypy 严格检查通过；改动文件 Ruff 通过。`factory_v2.py:4247` 存在一项修复前已有的无关 E501，未作扩范围修改。

## 审查结论

未发现 P0/P1。未引入场景、阵营或实体 ID 特判；checkpoint 与确定性回归通过。

残余风险：15/18 m/s 的数据仍是 `UNVALIDATED_BENCHMARK`。本次证明 L7 代理能产生可用运动，尚不能将其表述为经真实船体水动力数据标定的性能；后续如需对外发布该性能，应单独进行模型标定和验收。
