## 测量对象是什么

每个时间步配对 `G_t` 与 `S_(t+1)`：

- G 保留全部活动目标的类型、参数、优先级、约束和期限，排除任务 ID 与签发时间元数据。
- S 保留全部己方实体（包括固定设施）的 ID、阵营和生命周期、位置、速度、健康、能量、弹药、组件状态。
- 状态中不纳入 controller 命令副本，避免把同一命令在两端的重复存储误计为目标—状态联系。
- 不分箱、不把缺失值填零、不按有利结果挑实体；缺字段、实体 ID 重复或时钟错位直接报错。

这是在上述明确表示下计算的离散经验互信息，不是连续 KSG，不是干预因果互信息，也不是经过验证的通道容量。字段表示本身也是测量约定，不能声称已经覆盖所有可能的语义信息。

## 当前证据支持什么

1. 当前 Windows 环境能够完成至少这两场游戏场景的自然终局运行，并精确回放其接口目标序列。
2. 完整轨迹可以导出时间对齐的目标—状态测量，而不再依赖历史单实体位置投影。
3. 当前经验 MI 的可靠性有明显问题：联合表很稀疏，时序错位后依然得到较大的数值。IE-02 的原值与移位均值仅相差约 0.044 bit；不能把原值较高解释为已经证明更强耦合。

不能据此给出跨 seed 置信区间，不能将 IE-02 与 IE-01 的数值差归因于架构，也不能用正 MI 宣称分层定律得到验证。不同场景长度、实体数和目标支持均不同；场景间差异与接口效应尚未分离。

## 对后续实验的直接影响

完成八场景批次后，先独立审计真实终局和回放，再生成全八场景新测量快照。即使全部回放一致，正式 B_if 的估计有效性仍须单独验证。

正式协议需要先固定目标/状态编码与估计对象。原始目标带离散类型，执行状态同时含离散生命周期和连续运动量，因此不能把 JSON 标签转整数就套用普通连续 KSG。已有混合类型估计器的合成校准也不能自动解决当前轨迹的重复状态、稀有类别和时序依赖。需要在固定表示下检验这些条件，公开拒绝估计的原因；不得丢弃稀有类别后重新归一化、随意加入噪声或用零替代缺失结果。

三档接口条件应在同一场景、同一 seed 下配对，并记录实际目标变化；不能用三个不同场景替代三档干预。多个 seed 的独立重复和已验证的参考规划/执行组件仍是后续正式测量及归因的必要工作。目前规则组件无注入只能称为基线，不能默认是 oracle。

## 追加：近邻估计的样本支持检查

追加产物：`artifacts/hifi-interface-support-snapshot-v1/measurements.json`。前一快照保持不变；新快照仍只含上述两场完整原运行，新增支持诊断不改变原 MI 数值。

| 场景 | 目标类别样本数（排序） | 重复状态行数（各类别首次出现之外） | k=5 时样本不足类别的概率质量 |
|---|---|---:|---:|
| IE-01 | 1、8、10、22 | 17/41 | 1/41，约 2.44% |
| IE-02 | 1、1、27、30、32、37 | 25/128 | 2/128，约 1.56% |

两个场景在 k=3、5、10 下均不能满足“每个目标类别样本数大于 k”这一严格混合类型估计器的必要条件。完整声明状态存在完全重复，任何仅由这些字段确定的数值投影也不能自动消除这些重复。目标还分别只有 5、7 段连续取值区间；区间数不是独立样本量，但说明不能把全部时间步当成独立目标试验。

这些是当前编码下的具体失败原因，不是所有可能的 MI 估计方法都不可用的证明。下一步应明确选择并验证能够处理离散/连续混合状态的表示和估计协议，或采集新的独立样本，而非丢弃 1.56%–2.44% 的概率质量后宣称估计了原总体。重复回放也不能增加独立 seed 数。即使以后样本支持条件通过，连续密度与时序依赖仍需另外检查。

新增四项测试验证稀有类别质量、重复行计数、严格 k 边界及空/未对齐输入。最新全量测试 **73/73 通过**；录制器与正在运行的批次脚本均未修改。
