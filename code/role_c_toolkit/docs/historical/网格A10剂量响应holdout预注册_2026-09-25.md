# Grid A10 注入剂量响应 holdout 预注册

登记：2026-09-25，任何 holdout 运行前。用途：游戏智能体已知故障/层级标签诊断；不作军事用途结论。

## 研究问题

已完成的 seed100–119 高剂量四格在多个处理臂触及共同低分平台；seed120–124 的 0.25/0.50 先导则显示规则栈的故障效应可随 seed 变正、变负。本 holdout 依论文 OpenMDBench0830 §6.3 的效度目标，在新 seeds 上重检已知 planner fault、executor degradation 剂量响应及 mild-balanced 条件；检验事件是否作用在声明层、配对效用差能否按执行故障剂量排序。

## 冻结设计

- 独立 holdout seeds：125–144（20 seeds）；不并入 seeds100–119 的既有确认批，也不并入探索性 seeds120–124。
- 固定场景：grid complex / continuous，决策间隔 5；引擎与轨迹使用当前已记录的 4.0 grid source tree；故障包装器版本以 campaign manifest SHA256 固定。
- 故障实现：复用 `grid_factorial_fault.py` 中已审计的 `planner_wrong_assignment` 及 `action_hold`。planner-only 使用剂量 0.1；executor-only 使用 0.1、0.3、0.5 三臂；balanced mild 同时用 planner=0.1、executor=0.1。
- 每 seed 六条件：clean (0,0)、planner (.1,0)、executor (.0,.1)、executor (.0,.3)、executor (.0,.5)、balanced (.1,.1)。每条件原始运行及自身确定性决策重放。
- 主要结果量：引擎原始 composite `V`，不变换、不截断、不排除负损失或低分 seed。配对效应：`ΔP=V(clean)-V(planner)`；`ΔE_d=V(clean)-V(executor_d)`；`ΔI_bal=V(balanced)-V(planner)-V(executor_0.1)+V(clean)`。

## 预先锁定的验收判据

1. 完整性：每 seed 六条件原始/重放齐全；报告、trace、fault event hashes 一致；own replay 精确；源代码清单一致。任一错误均报告并保留，不用重跑替换失败格。
2. 注入边界：planner-only 只记录 planner 事件，executor-only 只记录 executor 事件，balanced 两类均有；每种 fault 在其 holdout 处理臂上跨 seeds 至少实际触发一次。零事件 seed 保留并计入效用 ITT 分析。
3. 执行剂量趋势：`mean(ΔE_.1) < mean(ΔE_.3) < mean(ΔE_.5)` 且两个 paired seed-level 差 `(ΔE_.3−ΔE_.1)` 与 `(ΔE_.5−ΔE_.3)` 的 95% bootstrap CI 下界均大于 0，才称为严格支持。否则判定该门未通过；不改剂量、不移除 seed、不以事件数代替效用。
4. planner/balanced 只作同样透明的配对效应和 seed bootstrap 描述，不在看结果后挑选显著对照或另设验收条件。
5. Bootstrap：seed 为唯一重抽样单位，10,000 次、PCG64 seed 20260925、双侧 percentile 95% CI。所有逐 seed 值、缺失、效应和事件数同时输出。

## 解释边界

本实验验证的是已知注入位置、确定性自身重放和此规则/启发式栈上的效用剂量响应。clean 组件并非独立证明的 oracle；它不等同于论文 §5.1 所需的 oracle-execution / oracle-planning / oracle-full 反事实，因此通过本协议也**不能单独宣称正式 ΔP/ΔE/ΔI oracle 归因已经验证**。若分数平台、负效应或非单调出现，均如实报告为未通过/设计诊断。高保真 LLM+GOAI 复制仍需真实 vLLM endpoint 和 IE-01–IE-08 场景复验。
