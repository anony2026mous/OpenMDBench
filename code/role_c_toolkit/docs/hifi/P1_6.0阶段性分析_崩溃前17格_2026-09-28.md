八局完整的 LLM 轨迹合计记录 `768` 次请求：请求错误 `0`、空回复 `0`，规划解析失败 `5`、旧计划沿用 `5`、真正规则回退 `0`。请求延迟中位数约 `23.7 s`，第 95 百分位约 `28.9 s`。`pure-llm` 两局合计 `92` 次命令屏蔽记录；这是一项执行约束计数，不能直接等同于 92 次独立模型故障。崩溃中断的第九局 `pure-llm` 请求未计入上述完整局分母，原始部分请求仍保存在批次目录。

**通俗解释：**虽然裁判把这 17 场都判成防守成功，有些设施已经失能，有些来袭目标已经闯入并投放过武器。尤其不能只看“击落了多少”：目标可能先投放、后被击落。纯 LLM 已完成的两场没有对水面目标开火记录，值得在补齐第三场后继续检查。模型服务器在完整局中没有断连，但少数规划输出解析失败后沿用了旧计划；崩溃局只有部分记录，不能算完成比赛。

## 4. 目前能说什么、仍缺什么

当前数据支持的结论仅为：在 IE-10 的这三个预定 seed 中，`llm` 相对 `rule` 的优势随 seed 翻转，`llm-rl` 相对 `rule-rl` 也未出现稳定正差；终局成功标签未能反映全部设施损失。IE-10 的空/面资源覆盖率、重复目标分配和逐时段未处理威胁持续时间尚缺可核验的 Goal/动作轨迹重建，不能仅凭发射数反推。**IE-11 尚无一局自然终局**，所以诱饵开火、误派、真主攻首次拦截和保弹指标目前均为“缺失”，不是 0；IE-10 的诱饵计数字段即使为 0，也不能充当 IE-11 的识骗结果。尚需重跑 IE-10、seed 203 的 `pure-llm`，完成 IE-11 的同设计六臂矩阵，再审计全部 36 格、计算纯基线门槛和跨场景是否变号。P2 的 weak/strong Goal 接口操纵尚未进行，本批 P1 数据不能证明分层耦合定律或接口因果效应。

**通俗解释：**第一道题已经显示“换个起点，谁更好可能反过来”，这本身是重要发现。要写成完整论文证据，还得补齐最后一格、跑第二道题，并另外检查规划层传下去的目标是否真的改变了执行层的行动。
