# 角色 C：6.0 冻结版三场景完整实验扩充规划

日期：2026-09-27。状态：**经讨论确定的后续实施规划，未表示实验已运行**。本文件与[36 小时最小实验设计报告](角色C_6.0冻结版最小实验设计报告_2026-09-27.md)配套，二者均应存放在 `source-code-6.0/source-code/openmd/doc/`。前者负责限时获取可信初步证据；本文件回答“继续补齐论文核心实证至少要做多少”。研究对象为**游戏智能体**。冻结的 grid、6.0 引擎和正式场景不改变设计或参数；若确需难度旋钮，只能以独立编号/哈希的派生场景、获准参数及开发 seed 标定，不能覆盖原包或对确认 seed 调参。

## 1. 研究边界：三场景能证明什么

固定三个场景：**IE-04 联合攻击**（负向/边界参照）、**IE-10 双轴同步**（跨域资源分配）、**IE-11 诱饵掩护**（语义情报与保弹）。选定依据是机制差异，而不是新 seed 上谁赢。若 IE-11 的实际提示或接触 ID 暴露“诱饵”真值，它只检验**对已声明公开情报的利用**；不得称“从无标签观测自主识骗”。只有在查看新成绩之前完成字段级审计，发现 IE-11 不适合原 D1 目标且 IE-06 经同样审计合格时，才允许按预先记录的**构念有效性**理由将语义场景替换为 IE-06；不得按分数替换。若 IE-06/IE-11 都不满足 D1，冻结条件下 D1 直接记未通过，更多 seed 无法修复。

三个 IE 场景足以写“冻结 6.0 空—面拦截场景家族内，分层架构的收益、边界和接口响应”；**不足以**声称普遍跨任务定律、四域算法适用性或原稿的“36 场景、五类任务、108 配置”。6.0 正式 registry 当前有 25 个 public ID，其中 IE-01～IE-14 共 14 个，且 `MD-AD-006-ISLAND-STRIKE` 与 IE-08 指向同包；现有纯 RL 支持说明的已验证域为 air/surface。若论文坚持 36/五类/四域及完整 oracle 因果归因，只增加这三个场景的运行局数**没有有限的补足规模**：须先获得正式交付的新增场景/可比架构和独立 oracle，再重新估时；否则修改论文贡献与适用范围。

**通俗解释：**三道题可以认真比较三种不同难点，但不能把成绩说成覆盖 36 道题或所有领域；如果题目直接告诉模型哪个是诱饵，答对只能说明它会读提示。

## 2. 完整核心实证的最低矩阵与统计门槛

所有估算均从**同版本、同场景、同 seed、同评分口径**的完整 episode 计算，角色 B 已有且经哈希、权重、包线审计合格的原始局可抵扣。主效用固定为 `strategy_scorecard.defender_score`，终局、设施加权存活、漏防、资源消耗与长尾作预定次指标。完成 36 小时冲刺的旧开发 seed 7/11 仍只作探索；新 seed 若未被看过可复用，但必须保留运行批次标签。

| 证据块 | 最低实验规模 | 含 LLM 完整局（上限估算） | 必须回答的问题 |
|---|---|---:|---|
| **A. 六臂主表** | IE-04/10/11 × **20 个新配对 seed** × 六臂：`rule-rule`、`llm-rule`、`rule-rl`、`llm-rl`、`rl`、`pure-llm`；共 360 局 | 3 种 LLM 臂 ×3 场景×20＝**180** | 两种混合架构各自相对三种纯架构，何时更好、何时更差；四格非加性如何变化 |
| **B. 接口预算** | IE-10 与 IE-11 各 weak/medium/strong ×20 seed；A 中同配置 strong 可复用；`rule-rl` 也做同三档作低成本操纵校验 | 2 场景×2 个新增档×20×`llm-rl`＝**80** | 三档是否真的改变 broker/Goal 编码、下一窗动作和效用；不是只改变提示字数 |

**合计规划：约 380 局含 LLM 的完整 episode**，另有约 260 局以上较便宜的规则/RL 主表和档位/故障校验；若 B 有合格同格数据，相应扣除，不能简单合并不同 tag。20 seed 是**最低启动样本**而不是保证精度：先用配对差的实际方差和预定最小有意义效应作盲化功效/精度检查，再按事先锁定的 seed 区块扩到 30 或 40；不因正负方向而决定是否追加。以正态近似、双侧 5% 水平、80% 功效为纯规划示例，若配对差标准差为 0.15/0.20、欲区分效用差 0.10，所需约 18/32 个 seed；真实设计须重新估算。tick、接触和重复 LLM 请求不得当作独立 seed；同 seed 重复请求用于估计模型波动，按 seed 聚类报告区间。

**通俗解释：**每一种系统在每道题上面对同样的 20 个随机开局；这样分数差才像“同一场比赛的两种打法”。20 次只是有机会看清中等差异，若开局运气波动大，还得补样本。

## 3. 三项核心方法的验收顺序

### 3.1 架构收益与公平性（A）

第一门是冻结 manifest：引擎/场景 resolved hash、评分代码、prompt/frontend、vLLM 模型与采样参数、纯 LLM 速度包线、RL 决策间隔/随机采样/速度来源、每个 checkpoint 内容哈希及元数据。只收 `strategy_scorecard.scored_weight != null` 且自然终局的同口径局；超时/中断局单独报发生率，不赋零也不删除。每场景报告六臂分布、逐 seed 配对差、成功/失守尾部与稳健区间；两种混合臂对三纯臂的六个比较预先指定主要对照和多重比较处理，不以总均值掩盖 IE-04 反例。

现有 `llm-rl` 候选 v9/v10 与 `rule-rl` v11/v12 的 `goal_source` 和训练轮数不一致。因此原四格的 `E`、`I` 只可先作**部署系统的描述性差值**。若论文要声称“仅换规划器/执行器”的因果主效应，需要额外的**共同冻结 RL 执行权重**跨两种规划器评测，或来源×部署的交叉评测并明确 OOD 区域；目标来源分别训练到相同轮数只是改善公平性，不能单独消除训练分布混淆。新权重是版本化实验产物，不修改冻结引擎/场景；训练数据、预算、选择规则与训练 seed 也需锁定。

### 3.2 耦合/公式（B、D）

先把**场景结构耦合**、**规划层独有且被允许提供的信息**、**目标接口被执行器实际使用**分开。IE-04/10/11 的结构差异只构成三个代表性条件，不能假定其 `C_info` 已形成单调等级；D1 以真实观测/提示字段审计为前提，D2 以最好纯基线的未饱和程度判断，D3 必须先有 Goal 字段、RL 编码、动作与效用的可检测档位差。旧 KSG 在大量稀有类别和重复连续状态中曾不可估，正式 `B_if` 估计器需用含点质量、稀有类、时间依赖和长短局的合成/空白对照校准；不可估写 `null`，不是零 bit。若时间不足以校准，改用“接口裁剪的系统效应”作为独立指标，不再沿用旧公式对 `B_if` 的强断言。

优先用同场景六臂分数计算 `P=V_llm-rule−V_rule-rule`、`E=V_rule-rl−V_rule-rule`、`I=V_llm-rl−V_llm-rule−V_rule-rl+V_rule-rule`，及 `B=max(V_rule-rule,V_rl,V_pure-llm)−V_rule-rule`；于是混合 A/B 相对最好纯臂分别为 `P−B` / `P+E+I−B`。这是**恒等式，不是因果定律**。理论部分另预定可失败的接口预测（如 Goal 档位无动作响应时，不应声称接口贡献）。若用本批数据总结新的耦合公式，必须标成探索性候选，并在**未用于构造公式**的新 seed 区块或新场景验证方向/边界；三场景即使重复很多 seed，也只支持该场景家族内的条件性规律，不支持普遍定律。后验改公式再用同一批数据“验证”不可接受。

### 3.3 归因（C）

外置包装器在 planner 输出或 executor 动作处注入，不改引擎、场景或权重；五类条件的故障概率/对象/窗口在确认 seed 前锁定。先要求 clean 的自身目标/动作重放逐局精确匹配，分叉后随机事件无法共用时将 estimand 降为相同 seed 分布的平均效果。展示盲判标签、逐 seed 效用损失、执行故障相邻剂量差的区间和负向例，不删零事件/反向 seed。历史 grid A10 的 20-seed 严格剂量响应未通过，因此不能预设“高保真 5/5 单调”。

论文若继续使用 **oracle planner/executor/full 的因果分解**，还需另建并在独立单域任务验证 oracle 质量，检查反事实目标合法、反馈适应及精确重放，再跑对应的三类反事实；上表的 120 局故障实验**不替代**该工作。如果 oracle 不存在或质量门失败，应把论文 C3 缩为“已知故障定位/反事实诊断原型”，不要称完整 oracle 因果归因。原稿 §5.1 执行损失的符号与正的 Table 3 数值不一致，也必须在定稿前统一。

**通俗解释：**先确认六种系统比较公平，再查目标命令是不是真在影响动作，最后用已知故障考诊断工具。即使“蒙眼实验”找对出错层级，也不等于已经拥有一个可靠的“完美规划器/执行器”。

## 4. 时间、资源与不能承诺的部分

6.0 实验规范记录含 LLM 臂约 0.35–0.43 tick/s；以本组场景常见 1100–1400 tick、提前终局与长尾并存的条件，**每完整局按 45–60 分钟作排程**。380 局约需 **285–380 小时单路 vLLM 推理**。若 36 小时冲刺最多完成 21 局并全部合格，仍约有 **270–360 小时新增单路推理**；便宜臂/重放另排约 15–35 小时机器时间。两路并发只有经过吞吐和正确性实测才可按接近半时估算，不能把两个请求数机械当作双倍速度。

建议日历安排：第 1–2 天完成 P0、IE-11 泄露审计、原始局可复用核对和注入/重放冒烟；之后约 2–3 周分批完成 A/B/C 的端点采集，同时做分析与自审；最后预留约 4–7 个工作日做统计、图表、负结果审计和论文主张修订。**总体按约 2–4 周、有单路端点时偏向上限安排**；这不是保证完成时间。若要等预算/共同权重训练、正式因果 MI 和独立 oracle，上述时间还应增加相应工程/训练期；oracle 缺失时无法给“只需再跑多少小时”的封顶承诺。若实际配对方差要求每格 30–40 seed，主表与档位成本按新增 seed 线性上升。

硬停机/降主张条件：冻结哈希/评分/包线混用；IE-11 真值泄露却仍标自主识骗；三档没有实际 Goal/动作操纵；估计器不可校准却填数；自身重放失败却称精确因果；没有 oracle 却写 oracle 归因。遇到这些问题，先修**实验包装/分析定义**或收窄论文，不许改冻结场景“调出”正结果。A、B、C 都完成也不能保证录用；最终判断还取决于主张范围、论述与审稿。

**通俗解释：**场景从六个缩成三个确实省掉不少运行时间，但还有校准尺子、检查因果回放和写清局限的固定成本；最难的 oracle 问题不是让机器多跑几天就能自动解决。

## 5. 交付、数据分层和与 36 小时报告的关系

- 两份规划文档都是 6.0 的**文档产物**，不写入旧版 `source-code-New-architecture`，更不把旧版引擎轨迹混入 6.0 新数据。
- 36 小时报告是 **P0 + 极小配对主表 + IE-10 strong/weak + 请求可靠性** 的第一批；本文件的 A/B/C 是后续“论文核心实证”矩阵，不能倒过来把第一批三 seed 写成 20-seed 完成。
- 输出需要可复算的 `manifest`、源/场景/checkpoint/LLM 哈希或版本、逐局原始报告与日志、自然终局/超时标签、目标/动作/注入事件、逐 seed 配对表、统计脚本与锁定的图表数据。开发 seed、旧 tag、场景定档 seed、公式推导 seed 与独立检验 seed 分表保存。
- 角色 B 负责六臂主表及纯架构成绩，角色 C 负责 D1/接口、故障定位、可靠性与公式证据审计；两个角色共用一份原始局，不重复运行。平台 C2 的 CSS/轮询 API、断线恢复、延迟注入、可复现性由对应负责人单独测试；这不等于三场景算法对比自动证明了平台贡献。
- 论文定稿前逐条对照主张与证据：若只有三 IE 场景，就把“36 场景/五类/四域普遍性”删改；若没有正式 MI，则不用 `B_if` bits；若没有独立 oracle，则不用 oracle 因果分解；若新公式由实验得出但未独立复核，就写候选公式及适用边界。

**通俗解释：**先跑的小批次能帮我们决定下一轮怎么跑，但不能直接充当下一轮的完整答卷。每一个论文句子都应能指回同版本的一张表和一批原始记录。
