## 0. 执行结论与不可承诺之处

**当前执行版是 36 小时冲刺，不是完整研究计划。**其最小交付为：① 冻结哈希、评分与架构公平性审计；② IE-10 为主、IE-11 为机制复核的同 seed 六臂成绩表（复用角色 B 合格轨迹）；③ IE-10 的一个目标接口裁剪对照；④ 全部 LLM 局的可靠性统计。规划/执行两类故障注入只在既有包装器能迅速通过 6.0 自身重放审计且时间有余时做。角色 C 不能为重复 B 的主表耗尽推理预算。IE-04 只复用合格既有数据作边界参照，本轮不新跑；grid 只复用冻结历史结果作方法风险与边界证据。若 36 小时结束后继续补齐论文核心实证，应转入同目录的[三场景完整实验扩充规划](角色C_6.0三场景完整实验扩充规划_2026-09-27.md)：该规划将 IE-04、IE-10、IE-11 作为三种预定机制，**不把本冲刺的 3 seed 结果冒充完整验证**。

旧方案中的 20-seed 扩展、两场景三档 LLM 全矩阵、重建正式 KSG、五型严格剂量响应、oracle 构建和难度旋钮定档，均**转为后续扩展，不是 36 小时交付门槛**。这套冲刺不能保证论文录用，也不能保证分层定律得到正结果；3 个新 seed 只能提供前瞻性小样本复核，不能支持普遍性或显著性结论。若关键信息/接口门禁失败，就保留边界或反例，不得换场景、筛 seed 或修改冻结参数制造通过。

**通俗解释：**现在要在一天半内交出一套可信的“小而完整”的证据，而不是追求把所有考题做完。没有测到的部分明确留给下一轮，不能写成已经验证。

6.0 高保真入口 `openmd/code/eval/run_episode.py` 的六种 `--planner` 选项如下。前四臂是规划层 × 执行层的 2×2；后两臂是无分层接口的单架构参照。

|---|---|---|---|

## 2. 论文主张—证据映射与 36 小时最小集合

原稿 Q1“混合是否更好”由 B 的六臂主表负责；C 在复用该表的同时处理 Q2 的接口机制、Q3 的有限诊断。这里的“六臂”是同一冻结场景/评分/包线/权重约定下的 `rule-rule`、`llm-rule`、`rule-rl`、`llm-rl`、`rl`、`pure-llm`，**不是**从不同 tag 和评分版本拼成的六个数字。先审计 B 已有同 seed 原始局，缺格才补跑。

| 优先级 | 本轮要做 | 样本与成本边界 | 可报告的上限 |
|---|---|---|---|
| **必做 P0** | 哈希/评分/包线/checkpoint/LLM 配置清单；IE-11 实际提示与接触 ID 审计；每条选中架构的接口冒烟 | 开始 3 小时内完成；无需完整 14 场景审计 | 版本与可比性状态 |
| **必做 P1** | IE-10 六臂同 seed 配对主表；再按剩余时间做 IE-11 同设计 | 先核对 3 个此前未用于开发的新 seed，例如 201–203；每个场景最多 9 个新 LLM episode，全部两场景最多 18 个；合格 B 轨迹抵扣 | 场景内、前瞻性**小样本**系统差异；不称稳健总体胜出 |
| **必做 P2** | IE-10 同一 `llm-rl` checkpoint 的 strong（已在 P1）与 weak 接口裁剪；廉价 `rule-rl` 先查目标字段/动作确实有响应 | 最多新增 3 个 `llm-rl` weak episode；若廉价操纵失败即不启动这些昂贵局 | 接口裁剪的系统效应；不称因果互信息或普遍耦合定律 |

**通俗解释：**先把 IE-10 的六种系统摆到同一赛道，再用 IE-11 看结论是否换个题就翻转。接口只加一个最有用的裁剪对照；三次新尝试不足以宣称普遍规律，但足以暴露错误方向或工程问题。

## 3. P0：先过的公平性和信息门禁

1. **同口径运行清单。** 每一行保留 `(scenario_resolved_hash, scenario_variant, seed, run_id, arm, output_tag, code_hash, checkpoint_hash, checkpoint_meta, LLM_model, backend, temperature, max_tokens, plan_interval, decision_interval, speed_source, rl_stochastic, pure_llm_envelope, frontend, score_version)`。`rl` 用无目标权重；`rule-rl` 只用 `goal_source=rule`；`llm-rl` 只用 `goal_source=llm`。对当前训练预算不等的四格，结果只能解释为**现有已训练系统组合的差异**，不得写成纯净的规划器主效应或跨层交互因果效应。若后续另行训练等预算权重，必须作为版本化的模型产物、事先固定训练配方和训练 seed；不属于改变冻结引擎/场景，但也不能与旧权重无标记混用。
2. **IE-11 信息泄露审计。** `agents.yaml` 的 `attack.timeline` 直接写出 `decoy screen`、出现时刻及无武器/转向性质；`run_episode.py` 将其变成 LLM 的 ROE 提示，`interception_graph.py` 将完整 timeline 送入图提示。场景实体 ID 又含 `intruder.decoy-*`，接触 ID 的后缀在图代码中用于实体归并。故必须保存实际传给三类臂的观测/提示摘要，逐字段确认：哪些是真正对玩家公开的简报、哪些是引擎真值、规则/RL 能否从 ID 看出标签、LLM 是否看到了不应公开的真值。**不修改冻结接口来“补公平”**；若确有真值暴露，IE-11 主张改为“利用已声明的公开情报”，不能当作隐藏诱饵推理 D1。单用 IE-11 的所有 seed 也不会创造新的诱饵语义类型。
3. **D1′ 与 D2 的最低限度审计。** 本轮不新建贪婪基线或重新定难度；从同版本运行日志标出资源分配错误和纯基线的成功/失败分布。最好纯基线按新 seed 上三类纯系统的同场景均值计算，不以 seed 7 单点 0.56–0.63 代替；若 `pure-llm` 缺格则明确“最好纯基线未确定”。接近上限/下限的场景保留为边界，不为获得正结果调旋钮。
4. **重放与随机源。** 对每个介入条件先做“自身目标/动作重放 = 原局”校验，终局分数、时刻、事件摘要和源哈希均比对。相同 `--seed` 只固定起点，不自动保证轨迹分叉后使用同一随机事件；若需强因果配对，应证明外生事件流可复用，做不到则把估计对象写成“相同 seed 分布下的平均系统效果”，不称逐事件精确反事实。

P0 的硬停止条件：哈希不一致、同格混评分口径、checkpoint 约定不明、纯 LLM 包线不等、结果被截断却当终局、重放不一致。失败时先修**实验封装/日志/分析**，不修改冻结引擎或场景去让数据变好。

**通俗解释：**IE-11 可能把“谁是诱饵”写在给模型看的任务说明里。模型按说明做对，说明它会使用情报；但不说明它能在完全没有提示时识破伪装。两种能力不能混写。

## 4. P1：信息辨别和跨域分配的具体测法

主结果 `V` 是同口径 `strategy_scorecard.defender_score`，终局成功/失败、加权设施存活、漏防率、发射/弹药、运行时长与尾部局占比作预定次指标；跨场景先算**场景内配对差**，不直接平均绝对分。IE-11 的机制终点从首次诱饵可见至真主攻出现后固定窗口，记录诱饵开火/误派、真实目标首次拦截时间、为第二波保留的弹药和最终防守效果。IE-10 在两个域同时进入窗口的预定时间段，记录空/面资源覆盖率、重复分配、未处理威胁持续时长和终局。所有窗口在确认 seed 运行前根据场景声明固定；不根据胜负事后挑时刻。

比较首先做 `llm-rule − rule-rule`（执行器同为规则），其次做 `llm-rl − rule-rl`（只作为当前训练产物的系统比较，不能在未等预算时称纯规划效应），并分别与 `rl`、`pure-llm` 的 B 主表交叉核对。IE-04 只在已有同口径数据完整时作探索性特异性参照，不在 36 小时内新跑。IE-11 的决策点审计使用 P1 原始局，不额外调用 LLM；先核对提示和 ID 是否暴露诱饵真值。D1 论文旧阈值（规则辨别 ≤60%、LLM ≥85%）只有在样本真/假标签平衡、分类时点预定、无真值泄露且区间有说服力时才使用；本轮默认只报告资源保留/误打描述和混淆表，**不以 3 seed 宣称 D1 通过**。

统计单位是 **seed**，不是 tick 或接触。时间预算下优先每格 3 个新 seed、每格一次完整局；LLM 随机性通过旧的同格重复记录和本批原始调用日志呈现，但**单次/seed 不能充分估计模型波动**。逐 seed 配对差、均值、终局模式和探索性区间同时给出；n=3 的 bootstrap 区间仅作不确定性提醒，不作精度或显著性保证。旧 seed 7/11 另列探索表，不能伪装成未使用确认数据。六条“两个混合臂分别超过三纯架构”的不等式只形成逐格核对表，本轮不能凭 3 seed 同时确立六条确认性主张。

**通俗解释：**IE-11 问“有没有把子弹浪费在已知诱饵上”，IE-10 问“空中和水面同时告急时有没有顾此失彼”。这比只看最后赢没赢更能解释规划层是否真的帮了忙。

## 5. P2：把接口耦合测成可解释的量

### 5.1 三个量必须分开

- **结构性任务耦合**：来自场景约束，如同时受压的域数、必须先后衔接的任务；在同一冻结场景中它基本固定，不应被 goal 裁剪“测出变化”。论文的 `C_action`/`C_intrinsic` 可作描述，但不会自动等于信息优势。
- **信息不对称 `C_info`**：先定义“规划层独有且玩家允许看到、执行层自身观测里没有的信息”及其可核验标签。IE-11 的公开 timeline 能提供候选语义信号，但要通过 P0 审计；一般的 `I(Goal;State)` 不是信息不对称。
- **接口使用 `B_if`**：旧论文 §5.2 的 KSG 值保留为“历史轨迹代理指标”，不能直接等同于因果传输。**本轮**只测 weak/strong 整局目标裁剪的可观察响应，不以 bits 冒称互信息。**后续正式因果 MI 验收**才需要在同一合法观测/决策点，对目标字段做随机化的合法替换，比较下一决策窗的动作分布；先确定有限离散的 `G`、`A_{t:t+h}` 和条件历史 `H_t`，按已记录的随机分配 `p(g|h)` 从 `P(A|do(G=g),H=h)` 构造干预分布，计算 `I_{do}(G;A|H)`，并报告支持、偏差校准及区间。不能把本轮整局裁剪或被动 MI 改名为因果 MI。

### 5.2 最小操纵和验收

原生 `--goal-granularity weak|medium|strong` 可用于接口裁剪；**本轮只做 strong 对 weak**，在同一规划器类型、同一 checkpoint、同一 plan/decision interval 下比较。先用廉价 `rule-rl` 在 IE-10 的 3 个新 seed 上比对原始 Goal、裁剪后 Goal、broker 接受的 Goal、RL goal block 与下一执行窗口动作。若字段没有实质差异、执行器未收到或动作完全无响应，记录 D3 操纵失败，不启动昂贵 LLM weak 局；不把 pooled tick 当独立样本。medium 与 IE-11 的三档矩阵留到后续。

廉价操纵通过后，以 IE-10 中 P1 的 `llm-rl` 默认/strong 完整局为参照，最多追加同 3 seed 的 weak 完整局。LLM 提示、模型、权重和规划频率固定；`v2_agent.py` 在规划器输出后裁剪 Goal，因此它测的是**改变接口规则后的整局总效应**。轨迹分叉后 LLM 后续输出也会改变，故不能称“同一串规划输出只改目标字段”的局部直接效应。主要报告 seed 内固定窗口的目标/动作响应与完整 episode 效用差；终局时长不同则联合报告公共事件窗与是否提前终局。合法目标置换及决策点精确反事实留到后续，除非现成代码已可审计复用。

历史 KSG 与高保真混合分布存在稀有类别、重复连续向量和时间相关问题：既有 4.0 规则轨迹 39/39 cell 为 `null`。**36 小时内不开发新的正式 KSG/因果 MI 估计器**，只给 Goal 字段变化、下一窗口动作响应和效用裁剪效应；把它们称为“可观察接口响应”，不称 bits 或正式 `B_if`。新估计器的离散点质量/稀有类别/长短局模拟校准属于后续扩展；旧 `null` 仍不得填 0。

**通俗解释：**“目标和行动同时变化”可能只是都被同一场战况推动。真正有说服力的是：战况相同、只改变传给执行器的合法目标，它的行动是否跟着变；如果不变，接口可能只是摆设。

## 6. P3：故障归因、反事实与可靠性

本轮先从 P1 轨迹做无新运行成本的失败位置审计。只有在既有外置注入包装器能在 6.0 上**快速通过原局—自身重放一致性**后，才于 IE-10 的廉价 `rule-rl` 参考系统追加零故障、规划 Goal 故障、执行动作故障三个条件；每个仍用同 3 新 seed，并记录注入概率、实际触发次数、时间和作用对象。零事件局按意向性分析保留；报告逐 seed `V(clean)-V(fault)` 和能否区分两类已知标签。历史 grid A10 20-seed holdout 未呈现严格单调，故本轮不做 0.1/0.3/0.5 完整剂量序列、不承诺五类 5/5 或严格单调。包装器适配超时/重放失败时，停止注入，只报告观察性失败分类，不称因果归因。

真正 `llm-rl` 的多故障复核、checkpoint 分叉和 oracle planning/execution/full 全部留到后续；本轮的两类廉价注入**不能**替代 oracle 组件归因。若未来构建 oracle，还须独立验证其质量、目标合法性、反馈适应性与精确重放。原稿 §5.1 的 `V(original)-V(oracle_E)` 与正的 Table 3 数值符号相反，未来报告要统一正损失口径；本轮若无 oracle，不输出 `ΔP/ΔE/ΔI` 的 oracle 标签，避免与第 7 节的四臂成绩分解项混淆。

可靠性同时计：原始 LLM 请求数、空/None 响应数、JSON 解析失败数、命令验证失败数、沿用旧计划次数、真正规则 fallback 次数、超时数、每次延迟 p50/p95，以及被截断 episode。`llm_planner.py` 有“失败后先复用旧计划，再 fallback”的路径，故 `fallback_count` **不是**总故障率。旧门槛“None/解析错误各 ≤5%”按请求数作分母，并以每场景/每 seed 给区间；失败局不从效用主分析中排除。

**通俗解释：**给规划器和执行器分别“蒙一下眼”，看诊断工具能否指出哪边出了问题。只有这项校准通过，才有资格谈真实系统的责任归属；而模型答不出来、答错格式或靠旧方案硬撑，都要如实算进表现。

## 7. 从原条件式转向可观测的分层盈亏分解

原稿 `ΔV = −c + f(C_info,B_if)·headroom(V_m)` 是可修订的研究假说，**不是实验必须遵守的真值**。本轮既没有独立有效 oracle 来定 `V*`，也没有可验收的高保真 `B_if`；在 36 小时内拟合任意 `f`、`c` 或指数曲线只会变成事后解释。因此优先用同一场景、同一新 seed 集六臂的可观察效用 `V`，建立不依赖未测量变量的**成绩分解**。所有 `V` 是新 seed 上同评分口径的均值，另给逐 seed 版本；`V_m = max(V_rule-rule, V_rl, V_pure-llm)` 是三种纯系统均值中的最大者，`B = V_m − V_rule-rule ≥ 0`。若任一纯臂缺失，就不假装已确定 `V_m`。

```text
P = V_llm-rule − V_rule-rule
E = V_rule-rl − V_rule-rule
I = V_llm-rl − V_llm-rule − V_rule-rl + V_rule-rule
B = V_m − V_rule-rule

ΔV_A = V_llm-rule − V_m = P − B
ΔV_B = V_llm-rl   − V_m = P + E + I − B
```

它给出两个明确的盈亏条件：**混合 A 赢过最强纯系统当且仅当 `P>B`；混合 B 当且仅当 `P+E+I>B`**。`P` 是固定规则执行器时的规划器差，`E` 是固定规则规划器时的执行系统差，`I` 是四格非加性，`B` 是纯架构竞争门槛。这个式子是精确的**代数恒等式/核算框架**，本身不会被数据“验证”，也不能单独当论文理论创新。由于两种目标条件 RL 权重的训练轮数与 goal source 不同，`E`、`I` 只能称部署系统差与非加性，**不是**无混淆的执行器因果效应或“耦合度”的直接测量。对 `V_m` 的选取、逐 seed 纯臂赢家变更和有限样本 max 偏差，均作敏感性表；不只公布一个漂亮的平均值。

理论贡献须来自额外可失败的**接口机制命题**，而非上面的恒等式：若 weak 与 strong 的实际 Goal 字段、RL 编码和下一窗动作没有可复现差异，就不能把 `I` 或混合收益归因于目标接口；若 IE-10 有响应而 IE-11 没有或反向，则新理论必须写成场景条件性。此次只以新 seed 检查 IE-10 的接口裁剪、对 IE-11 做小样本外观复核，不拟合跨场景单调函数；IE-10/11 场景本身已从历史数据选出，新 seed 是**新随机起点复核**，不是独立新场景验证。

若看完结果后形成比原稿更合适的耦合公式，把它明确标为 **v2 探索性候选**，附推导所用场景/seed、预期失败条件、与旧公式差异；**不能用同一批构造公式的数据再声称验证了它**。只有下一批未参与构造的 seed/场景成功预测其方向和边界时，才升级为受支持的经验定律。本轮可以报告“候选公式 + 有限机制证据”，不承诺“分层定律已证实”。论文也需限制旧 grid KSG/五型归因与高保真新结果的适用范围，不再用旧 5/5 或正区间表述替代复核。

**通俗解释：**新式子先像账本，清楚记下规划、执行、两层配合各贡献多少，以及纯架构有多强；账本一定算得平，却不是自然定律。真正要验证的是“接口起作用时，哪类题让这些贡献改变”，这需要下轮独立试题继续检验。
