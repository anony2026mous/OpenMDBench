本报告执行[6.0 最小实验设计](../source-code/openmd/doc/角色C_6.0冻结版最小实验设计报告_2026-09-27.md)的“必做 P1”，对象是游戏智能体仿真评测。预定 IE-10-DUAL-AXIS-PINCER 和 IE-11-DECOY-SCREEN 两个场景，确认性 seed 为 201、202、203，每个 seed 对照六个部署系统：`rule`（规则规划+规则执行，即 `rule-rule`）、`llm`（LLM 规划+规则执行，即 `llm-rule`）、`rule-rl`、`llm-rl`、`rl`、`pure-llm`。先做场景内同 seed 配对，不跨场景直接平均绝对分。IE-10 检查双域同时分配；IE-11 在无直接角色标签输入的条件下检查诱饵屏障后的资源使用。IE-04 和旧 grid 不并入本批主表。

**通俗解释：**我们锁住试卷、模型服务器和每位选手的程序版本，但这些选手并不是接受完全一样训练、跑完全一样速度的“只换一个零件”对照。可比较实际产品表现，不能把差值全归功于某一个组件。

## 3. 入表、指标与统计方法

主效用 `V` 固定为同一评分代码的 `strategy_scorecard.defender_score`。只有原始报告显示自然终局、非中止、`scored_weight != null`，且场景/代码/权重/包装器/报告/事件/请求哈希一致时，才进入主表；运行中的快照和开发性 seed 9901 均不得入表。每格保存终局模式、加权设施存活、设施失能数、空中拦截/漏防/真实投放、表面层、己方发射数与弹药效率、运行 tick/耗时。终局状态与设施存活分别报告：引擎判为防守成功并不自动意味着所有设施仍可用。逐 seed 配对差与场景内均值同时报告，n=3 的 bootstrap 区间只作探索性不确定性提示，不作显著性或总体优越性证明。当前批次审计输出为[`p1_cells.csv`](artifacts/p1_manual_20260927_b1/p1_cells.csv)、[`p1_paired.csv`](artifacts/p1_manual_20260927_b1/p1_paired.csv)、[`p1_mechanism.csv`](artifacts/p1_manual_20260927_b1/p1_mechanism.csv)、[`p1_summary.json`](artifacts/p1_manual_20260927_b1/p1_summary.json)及[缺格表](artifacts/p1_manual_20260927_b1/p1_missing_or_ineligible.json)。

IE-11 的诱饵误打由真实执行的 `fire` 事件目标与报告中的实体标签复算，不能用修复前依赖目标 ID 字符串的 `layered_metrics.fires_decoy`。评分器的空中 `raiders` 可能同时包含诱饵，所以另列仅真实威胁的拦截、漏防和投放率。机制窗口在 IE-11 确认性局开始前固定为主攻 tick 150 之前与之后的 tick 150–249；若日志不足以恢复某个预定指标，则标“不可得”，不推断补值。

**通俗解释：**要等一场真正打完，且能证明用的是同一版程序和评分尺，分数才算数。诱饵不能因为编号改了就被统计成“没有误打”；我们会回看实际开火记录。三个随机起点太少，只能作谨慎的初步比较。

## 7. 分层盈亏账本与理论解释

按每臂三 seed 均值计算 `P=V_llm−V_rule`、`E=V_rule-rl−V_rule`、`I=V_llm-rl−V_llm−V_rule-rl+V_rule`；`V_m=max(V_rule,V_rl,V_pure-llm)`，`B=V_m−V_rule`。本场景结果为：

| 核算量 | IE-10 数值 | 含义 |
|---|---:|---|
| `P` | **+0.0294** | 规则执行器固定时，LLM 规划与规则规划的部署成绩差 |
| `E` | **+0.0532** | 规则规划器固定时，两种执行系统的部署成绩差 |
| `I` | **−0.0934** | 四格非加性差额；不能直接称因果耦合度 |
| `V_m` | **0.7610** | 三种纯架构均值中的最高者：`rule-rule` |
| `B` | **0.0000** | 最强纯架构相对 `rule-rule` 的均值门槛 |
| `ΔV_A=P−B` | **+0.0294** | `llm-rule` 相对最强纯架构的均值优势 |
| `ΔV_B=P+E+I−B` | **−0.0108** | `llm-rl` 相对最强纯架构的均值劣势 |

机器核算的 `ΔV_B` 恒等式残差为 **0**。按“先求每臂均值，再选最强纯臂”的预定定义，混合 A 满足 `P>B`，混合 B 不满足 `P+E+I>B`；但若改为**逐 seed 各自选最强纯臂再平均**，A/B 的平均优势分别只有 **+0.0180/−0.0222**，且逐 seed 有正有负。这两个 estimand 不应混同。代数账本本身不会被数据“验证”；P2 Goal 接口操纵尚未进行，且 `rule-rl`/`llm-rl` 的训练来源和轮数不同，所以 `E`、`I` 仍只是当前已部署系统差与非加性，不是无混淆的组件因果效应或干预式互信息。

**通俗解释：**按预定平均分口径，LLM＋规则刚好越过了纯系统门槛，LLM＋RL 没越过。但优势很小且随起点翻转；这说明的是这道题上的成绩，不等于证明“接口耦合有效”。

## 8. LLM 可靠性、长尾与限制

IE-10 的 **9 局合格 LLM 完整局**合计 **878** 次请求：请求错误 **0**、空回复 **0**，规划解析失败 **5**、旧计划沿用 **5**、真正规则 fallback **0**。请求延迟 p50 约 **22.7 秒**、p95 约 **28.5 秒**。`pure-llm` 三局累计命令屏蔽 **159** 次；这是一项执行约束计数，不等于 159 次独立模型故障。崩溃的 `a1` 是独立中断尝试，其部分请求不加入合格完整局的 878 次分母；不能把 `fallback_count=0` 解读为“没有任何规划故障”。详细见 [`p1_reliability.json`](artifacts/p1_manual_20260927_b1/p1_reliability.json)。

限制包括：单场景仅 3 个 seed，LLM 同 seed 随机波动未充分测量；`rule-rl` 和 `llm-rl` 权重训练条件不等，纯 RL 速度约定也不完全相同；场景从既有探索中选出；IE-11 尚无结果；P2 接口机制和 P3b 故障注入尚未完成。故可报告 IE-10 的前瞻性小样本系统差异，不能声称普遍架构优越、耦合定律已证实或完整因果归因。

**通俗解释：**服务器总体稳定，但有 5 次规划文本没解析成功，系统沿用了旧计划；设备崩溃的旧尝试也如实保留。漂亮的平均数不能抹去样本少和训练条件不同这些限制。
