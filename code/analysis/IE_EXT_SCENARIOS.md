## 1. 怎么做到"不动方法"

| 约束 | 做法 | 证据 |
|---|---|---|
| 不改引擎 Python | 新场景是纯声明式数据包（`scenario.yaml` + `agents.yaml`） | 只新增 6 个目录 + 6 条 registry 记录 |
| 不动老场景 | 生成器**只写新包**；老 7 包 SHA-256 前后逐字节比对 | 每次生成都做，不一致即中止 |
| 不动 catalog | 新场景复用 `catalog_bundle: ie_set`，不新增/不改资源 | `ie_set.yaml` mtime 未变（4278 分钟前写入） |
| 不动观测/动作张量 | 场景规模必须落在固定尺寸内：我方实体 ≤ `MAX_UNITS`=16、同屏接触 ≤ `MAX_CONTACTS`=20 | 实测最大 15 / 12（`_gen_ie_set_ext.py` 内置断言） |
| 不改 RL/LLM 配置 | 所有旋钮只走 `pressure` 表（数量/ingress/弹药）与包声明（雾、波次、时长） | 与老场景同一套构造函数 |

难度旋钮**只用**用户点名的五类：敌我双方无人机数量、无人船数量、天气、初始布局、
红方进攻策略（波次/轴向/诱饵/时序）。**武器参数一个没动**（面面弹 15 m/s 是有意设计）。

## 2. 六个场景

| id | 名称 | 设计意图（难度轴） |
|---|---|---|
| **IE-09** | 分波次双层突防 | 空中**两波错开 250 tick**（t=0 两架 / t=250 两架）+ 水面一支。考察"打完第一波还剩多少弹给第二波" |
| **IE-10** | 双轴钳形夹击 | 空中自东北、水面自东南，**几乎同时**进入武器窗口（与 IE-04 的刻意错开相反），考察同一时刻的跨域分配 |
| **IE-11** | 诱饵掩护主攻 | **诱饵前置**：2 架无武器诱饵 t=0 先出并在 t=150 转向脱离，真实空中主攻延迟到 t=150 才出现，直接惩罚"见接触就打" |
| **IE-12** | 雾中多向渗透 | **雾提前到 t=150**（早于 IE-06 的 600 与 IE-07 的 400），三向同时进入同一水上目标 |
| **IE-13** | 纵深双目标突击 | **纵深双目标**：陆上指挥所（远，需前出拦截）与港区远侧码头（近）同时受压，权重不同（1.5 / 1.0） |
| **IE-14** | 三波饱和突击 | **波次密度**：t=0 / t=300 / t=600 三波共 7 机 5 船，全程持续施压（老场景最多两波） |

## 3. 难度落点（实测，seed 7，当前评分口径）

| id | `rule-rule`(p18) | `rl`(rlb2) | `rule-rl`(v12, di5) | 带内? |
|---|---|---|---|---|
| IE-09 | 0.5864 | 0.6444 | 0.6956 | ✓ |
| IE-10 | 0.6331 | 0.6477 | 0.8141 | ✓ |
| IE-11 | 0.5587 | 0.1733 | 0.7754 | ✓ |
| IE-12 | **0.8680**（我机5/我船5，最终版） | 待补（旧版 0.3837） | 待补（旧版 0.3878） | ✓（偏易端） |
| IE-13 | 0.6422 | 0.3540 | 0.9149 | ✓ |
| IE-14 | 0.6001 | 0.6241 | 0.7120 | ✓ |

**六个全部落在 IE-01…IE-08 的难度带（0.4846–1.0000）之内。** IE-12 位于带的偏易端，
原因是它在两个域上都是刀刃（见 §4），整数兵力下取不到中段；因此**该场景应看"守住率"**
（多种子）而不是单点分数，`rl`/`rule-rl` 的读数需在最终版上重测。

**参考带**（老场景 `rule-rule`）：IE-08 0.4846 ← IE-06 0.6204 ← IE-05 0.6840 ← IE-07 0.7210
← IE-04 0.8707 ← IE-01 0.8877 ← IE-02 0.8989 ← IE-03 1.0000。

**已成立的两条主效应（新六场景，seed 7，无 LLM）**：

* `rule-rl` > `rule-rule`：**6/6**（Δ +0.11 ~ +0.27）
* `rule-rl` > `rl`：**6/6**（Δ +0.05 ~ +0.60）

## 4. IE-12 的定档过程（记录一次典型的"刀刃"标定）

这些场景的结局近似**二值**（守住 ≈0.86 / 失守 ≈0.35），因此单点分数会跳：

| 轮次 | 我机 | 我船 | ingress | `rule-rule` | 结论 |
|---|---|---|---|---|---|
| 1 | 5 | 5 | 0.80 | **0.8633** | 偏饱和（零损失全歼，`facilities` 层满分）→ 判别力弱 |
| 2 | 4 | 5 | 0.80 | **0.3476** | **过头**：低于带底 0.4846 ⇒ 对空是刀刃（少一架就翻） |
| 3 | 5 | 5 | 0.78 | **0.8680** | ingress 微调无效，仍偏易 |
| 4 | 5 | 4 | 0.78 | **0.4018** | **过头**：对水同样是刀刃（少一艘就翻） |

**最终取第 3 版（我机 5 / 我船 5 / ingress 0.78 ⇒ 0.8680）**：EDM 两域同时满编，
读数落在带内。整数兵力下不存在中间档 —— 减任何一边都直接翻成失守。

教训（写进方法学）：对这类**二值结局**场景，单种子单点分数不是难度指标，**守住率才是**；
定档要沿"没被翻过去的那一侧"找**连续**旋钮（弹药数、雾 tick、波次时刻），
而不是在已经位于刀刃的**整数兵力**上加减。下一轮若需要中段难度，应改
`blue_ammo`（每架 3→2 发是连续化的对空火力）或把雾推迟到 t=600。
