# E11 判别—价值跨场景对照实验设计 v1

执行依据：`OpenMDBench_实验强化清单_<author-B>_20261003_1205.md`（v8）§3.5；只负责实验，不编辑论文。引擎、原生场景、路线、角色设计和接触ID均不得修改。

## 一、问题与预先固定的解释边界

在同一个场景层面，受控判别上的 LLM 信息优势 Cinfo 与分层栈的综合价值优势是否必须同向？若 Cinfo≤0 仍同时出现正分层收益，就说明“受控判别优势”不是这些收益的必要伴随条件。

主对照是 Cinfo=LLM 平衡准确率减受限数值判别器平衡准确率，以及 ΔA=LLM+Rule−最好纯基线、ΔB=LLM+RL−最好纯基线。数值判别器是训练得到的 L2 逻辑回归，不是游戏中的 Rule 控制器。

跨场景并列不能单独识别“价值唯一来自语义分解”的因果机制，也不能排除所有形式的感知/信息优势。受控离线刺激集不等同原生在线自主识骗。Cinfo与Δ不是同seed配对观测，不构造跨批次差分或合并置信区间。

## 三、第二层：目标协议和必须满足的场景前置条件

目标是在第一层之外追加2–4个独立、已冻结、具有同E10离线真假契约的场景，最终总数4–6。额外场景不能由既有场景的新seed、同一个场景换别名或两种混合架构重复计数。

冻结注册表静态核查目前只有IE-06和IE-11双类齐全。IE-12有雾效但没有该契约下的诱饵；其余IE场景也没有此类诱饵。`decoy min / fog screen`尚无可对齐正式包。MD-AD-004不同武器/意图契约不可直接塞入E10；不自行改标签、不改场景，也不构造缺少负类的伪平衡实验。

因此第二层的实际仿真与LLM采样暂停，等待用户提供额外已冻结场景编号、包路径、对应价值成绩批次和标签契约。若必须新建场景，需单独授权并另冻版本。

额外场景到位后的执行规范：

- 每个场景10个开发seed及10个独立确认seed；拟预留开发20201–20210、确认20301–20310，启动前核对既有批次未使用，另建扩展批次。
- 每场景固定60确认事件（30真实+30诱饵），按E10水填充分配，在每seed内保持双类等量，10seed全覆盖；任一seed无双类或总覆盖不足则记录阻断，不替换不利seed、不复制事件、不事后改变标签。
- 原生Rule+GOAI完整局；plan10/decision5；每源局与未插桩影子局配对审计，物理轨迹、动作、终局、tick、分数一致后才入选。8次历史、每5tick采样、跨度≤40、≥4独立传感器观测tick、stride1、空域高度>10m，完全沿用E10。
- 数值主通道为当前位置xyz/10000、confidence、quality、age/10；辅助完整当前172维。新场景只能在其开发seed上按E10的四fold线性/逐元素平方L2逻辑回归（λ=.01/.1/1/10）拟合，冻结后预测，不在确认成绩上调整。场景间不合并训练或确认统计。
- LLM采用相同匿名受控历史简报字段策略、SYSTEM、JSON schema；Qwen3.8-27B、temperature0、关闭思考、max_tokens128；四并发请求分配至8101/8102。原生场景若设施布局与E10不同，先明确字段映射并冻结；不能在无说明情况下更换语义。
- 仿真最多8并发，所有内部CPU线程1；只使用新输出目录，不停止或改写E1队列。无须重跑已完成E10。
- 场景内采用20,000次seed聚类bootstrap CI（另报告seed等权敏感性）；跨场景单位是唯一场景，n=4–6，不将事件、架构或所有seed堆成跨场景样本。
- 使用原冻结主价值成绩；若额外场景缺少可匹配价值结果，单独说明并补设计，不能使用别的场景收益替代。
