# 三臂无情报实验：结果与结论说明

> 面向论文写作的结论说明文档
> 生成时间：2026-09-28　|　数据版本：withheld 口径，4 种子（159/168 格，seed 17 收尾中）
> 全部数字由脚本从原始实验报告自动生成，可复算

---

## 摘要（一段话）

本实验在 14 个拦截交战场景上，用统一的「无情报」口径（提示词不含任何敌方作战信息），
比较了 **LLM+规则执行**、**LLM+RL 执行**、**纯 LLM 端到端** 三个 LLM 臂，
以及 **纯规则**、**纯 RL** 两条单一架构基线。结论是：
**分层架构（LLM 负责高层意图、成熟控制器负责执行）显著优于任何单一架构**；
**纯 LLM 端到端不可行，且差距是量级性的而非可调优的**；
此外发现一个反直觉结果——**撤掉提示词中的敌方情报不损害混合臂性能，反在多数场景上略微提升**，
原因是旧提示词包含一条会误导决策的错误指令。

**论文的核心贡献不是"LLM 能打赢"，而是"LLM 该放在哪一层，以及为什么"**，
并以严格的口径控制与稳定性判据证明该结论不是抽签结果。

## 一、实验设置

### 1.1 口径定义

| 项目 | 内容 |
|---|---|
| **主口径** | `--llm-briefing withheld`：提示词**不含任何敌方情报**——无波次数量、无到达时刻、无进攻方位、无意图，亦无兵力数字 |
| **对照口径** | `declared`：历史口径，逐波披露 `spawn_tick / count / axis / behavior`（**含未来真值**），仅用于复现 2026-09-27 之前的旧读数 |
| 场景 | 14 个 IE 拦截交战场景 |
| 种子 | 7 / 11 / 13 / 17 |
| LLM | Qwen3.8-27B，温度 0.1，规划节奏 10 tick |
| 基线 | `rule-rule`、`rl` **复用归档数据，不重跑** |

### 1.2 为什么必须"无情报"

实测确认 `"armed vs decoy"`（哪几架携带武器、哪几架是诱饵）**不是观测字段**——
观测只包含位置、置信度、观测者、标签。因此任何兵力数字都只能来自场景声明，
而两条基线臂**从不读取该声明**。给出即为特权信息，与措辞无关，对照不再公平。

### 1.3 指标

`strategy_scorecard.defender_score`。该值**本身即**按适用层重新归一化后的加权平均
（`strategy_metrics.py:625-629`）：

```
scored_weight  = Σ w[k]   （k 取 applicable 层）
defender_score = Σ layers[k]·w[k] / scored_weight
```

不适用的层（如无空中来袭时的"拦截纵深"）**退出加权平均**，剩余权重重新归一化。
每局均做独立复算校验（用 `layers × layer_weights × layer_applicability` 反算），
偏差 > 5e-4 的局直接剔除。

## 二、主要结论

### 结论 1（主结论）：分层架构显著优于单一架构

| 臂 | 全局均值 | 标准差 | 种子≥3 覆盖 | 均值胜 `rule-rule` | 均值胜 `RL` | 严格判据 STABLE 条数 |
|---|---|---|---|---|---|---|
| **LLM+RL**（LLM 规划 + RL 执行） | **0.8076** | **0.1264** | 14/14 | **12/14** | **13/14** | **11** |
| **LLM+rule**（LLM 规划 + 规则执行） | 0.7709 | 0.1540 | 14/14 | 11/14 | 12/14 | 8 |
| rule+rule（纯规则基线） | 0.7036 | 0.2195 | 14/14 | — | 12/14 | — |
| RL（纯 RL 基线） | 0.6552 | 0.2138 | 14/14 | 2/14 | — | — |
| pure-LLM（纯 LLM 端到端） | 0.4297 | 0.2401 | 14/14 | **0/14** | 4/14 | **0** |

**论点**：LLM 擅长**高层意图理解与目标分配**，而**执行层必须交给成熟控制器**
（规则或 RL）才能把意图稳定落地。

**关键细节**：`LLM+RL` 不仅均值最高，**方差也最小（sd 0.126 vs LLM+rule 的 0.154）**。
这是一个很强的论据——**RL 执行层比规则执行层更稳定**，而非仅仅是"分数高一点"。

### 结论 2：纯 LLM 端到端不可行，且差距是量级性的

pure-LLM 在 **14 个场景中 0 个**能通过严格判据胜过任一基线，**10 个场景明确落后**：

| 场景 | pure-LLM 落后于 rule+rule | 落后于 RL |
|---|---|---|
| IE-02 | **−0.703** | −0.696 |
| IE-05 | **−0.580** | −0.520 |
| IE-04 | **−0.535** | −0.410 |
| IE-01 | −0.330 | **−0.515** |
| IE-14 | −0.468 | −0.187 |
| IE-11 | −0.348 | — |
| IE-06 | −0.200 | −0.194 |
| IE-09 | −0.186 | — |
| IE-10 | −0.180 | −0.108 |
| IE-12 | −0.163 | −0.093 |

**论文定位建议**：把 pure-LLM 作为**对照组**用于论证"为什么需要分层"，
而不是作为候选方案去优化。0.43 vs 0.70+ 的差距不是提示词调优能弥补的。

### 结论 3（反直觉发现）：撤掉敌方情报不损害混合臂，且在多数场景上略微提升

**读法**：两个混合臂在多数场景上"不给情报"反而更好，但**效应不均匀**——
IE-02/IE-03 提升明显（+0.12），IE-04/IE-10/IE-12/IE-14 略有下降。
因此**稳妥的表述是"撤掉敌方情报不损害、并在多数场景上略微提升混合臂性能"**，
而不是"撤掉情报一定更好"。pure-LLM 则明确受损（−0.085，且 IE-04 塌 0.459），
说明它是唯一真正依赖情报来做目标分配的臂。

**机理（已定位到具体缺陷）**：IE-11 场景中，真正的主攻波 `real air package`
（4 架武装无人机）的行为描述文本是
*"the four armed UAVs appear only after the decoys have already drawn attention"*，
其中含 "decoys" 一词。旧实现用 `"decoy" in text` 做子串匹配，
**于是这 4 架主攻被判定为非威胁**，提示词里出现：

> `real air package … is declared NON-THREAT … do NOT intercept or fire at it`

删掉情报 = 删掉这条错误指令。

**引擎侧的独立证据**（来自引擎自身的 ROE 记账，不是提示词复述）：

| 指标 | declared | withheld | 变化 |
|---|---|---|---|
| 威胁中和率 `threat_neutralization_rate` | 0.811 | **1.000** | +0.189 |
| 开火总数 | 11.79 | 6.33 | −5.46 |
| 误击诱饵弹数 `fires_decoy` | 0.134 | **0.000** | −0.134 |
| 误击民用弹数 | 0 | 0 | — |

**论文价值**：这是一个可写成独立贡献点的发现——**不恰当的情报注入比不给情报更糟；
"信息更多"不等于"决策更好"**。且该缺陷已从结构上消除（分类改为按武器装订判定，
措辞无法再翻转分类）。

## 三、判定表（三种子/四种子，严格判据）

### 3.1 稳定性判据定义

**三合判据**（本项目自定义，用于抵抗种间方差）：

```
STABLE  ⇔  均值胜  ∧  逐种子全胜  ∧  分半都胜
```

- **均值胜**：本臂均值 > 对手均值
- **逐种子全胜**：本臂**每一个**种子族的均值 > 对手**全部**种子族的均值
- **分半都胜**：按均值排序分半后，两半的均值都仍高于对手均值

仅均值胜记 `mean-only`；均值落后记 `LOSES`。

**为什么需要这个判据**：实测到同场景不同种子差可达 **0.35**（IE-03：1.000 / 0.650 / 0.631；
IE-08：0.649 / 0.282 / 0.553）。**只看单种子会得出"某臂在某场景碾压"的错误结论，
三种子一看是抽签。** 这是本工作方法论上的核心严谨性来源。

## 五、方法论严谨性（审稿人会问，必须写进去）

### 5.1 基线不漂移的证据链

本工作对共用代码做过改动（情报口径相关），审稿人必然质疑"你怎么证明基线没被影响"。证据：

| 检验 | 方法 | 结果 |
|---|---|---|
| **场景包身份** | 归档 vs 现行，逐目录逐文件 SHA256 | **14/14 逐字节一致** |
| **基线代码身份** | `rule_planner.py` / `v2_executor.py` / `rl_executor.py` / `rl_agent.py` / `strategy_metrics.py` / `attack_driver.py` 等 SHA256 | **全部 IDENTICAL** |
| **代码 A/B 对照** | 把修改前的代码放入沙箱（`PYTHONPATH` 置前），与现行代码跑同场景同种子，逐字段比对 | **22 字段 0 差异**，已覆盖 IE-01/02/05/06/09/11 六个场景 |
| **同代码复跑确定性** | 同代码连跑两局 | 16 个决策级字段全一致 |

**改动范围已逐 hunk 列清**：`run_episode.py` 4 处（3 处情报通道 + 1 处日志接口缺陷修复）、
`llm_planner.py` 2 处、`pure_llm_agent.py` 13 处，**全部落在提示词或情报通道**。
反向扫描非 LLM 模块命中 `briefing|roe_notes|speed_range` = **0**。

### 5.2 口径可复核

每局报告带 `briefing` 字段，但**读取路径有两个**，只查一个会漏：

| 臂 | 落盘位置 |
|---|---|
| `pure-llm` | `defender.briefing` |
| `llm-rule` / `llm-rl` | **`defender.planner.briefing`** |

此外 `pure-llm` 报告带 `speed_max_by_tag`，用于核对速度包线一致性
（IE-08 声明 40 m/s，其余 43 m/s）。

### 5.3 评分口径的易错点

`defender_score` **本身就是**归一化值，**不可再除 `scored_weight`**
（本工作早期犯过此错，把 0.90 显示成 1.00，已修正并加独立复算校验）。
归档中另有旧口径 `legacy_defender_score_all_layers`（全层恒定分母，可出现 >1.0），
但**不在 LLM 臂样本内**；所有分析脚本都做逐局口径判定。

### 5.4 基线策略身份必须锁定

归档的 `rl` 不是单一策略，混有 5 个 checkpoint。本工作**锁定单一身份**
`theta_rl_legacy2.npz`（`obs_dim=2866`，唯一带训练溯源且 `decision_interval=5`
与训练值一致者），共 64 局、覆盖 14/14 场景。
**跨 checkpoint 求平均会得到"不属于任何真实策略"的数字。**

## 六、已知限制（必须与结论同时报告）

1. **同 seed 不是重放**：LLM 端点在约 1.3k token 的真实提示词上**非确定**
   （同一请求 4 次输出互异；19 token 短提示词 5/5 相同）。
   固定 seed 对 LLM 臂是**一次独立复现**，不是同一条轨迹的重演。
   表述必须写"同 seed 条件下的独立复现"，**不能写"同 seed 配对"**。
   引擎侧确定性已单独验证（§5.1）。

2. **种间方差不可忽视**：`LLM+rule` 在 IE-03 上 s7=1.000 / s11=0.650 / s13=0.631；
   在 IE-08 上 s7=0.649 / s11=0.282 / s13=0.553。
   **单种子排名不可作为结论**——这是三合判据存在的理由。

3. **局长不是结果指标**：终局由 `rule.intruders-destroyed`（歼灭全部已生成来袭者）
   或场景声明的 tick 触发，不同臂在同场景会跑不同 tick 数。计分按战果而非时长。

4. **终局结构对双方公平**：14 个场景终局规则同构——成功只能来自"全歼"或"跑满声明时长"；
   两个侧面条件是**失败**结果，不存在"打不过就提前结束以逃避扣分"的路径。
   且 `rule.intruders-destroyed` 的 selector **含 `scheduled`**，未生成波次保持计数 > 0，
   该规则**不可能在后波未出现时触发**。

5. **数据完整性**：当前 159/168 格（seed 17 收尾中）。
   所有格子均带 `withheld` 口径字段，**0 局 aborted**。

## 八、复算方式

全部数字均由脚本从原始报告自动生成，可复算：

```powershell
$env:PYTHONUTF8='1'; $env:PYTHONIOENCODING='utf-8'
$env:PYTHONPATH='C:\Code\source-code\openmd\source-code\source_codes;C:\Code\source-code\openmd\code\eval'
$env:OPENMDBENCH_ROOT='C:\Code\source-code\openmd\source-code\source_codes'
Set-Location 'C:\Code\source-code\openmd\code\eval'
$py = 'C:\Code\source-code\source_codes\.venv\Scripts\python.exe'

& $py _w1_results_doc.py          # 本文档（THE_WITHHELD_RESULTS.md）
& $py _w1_p3_analysis.py          # 控制台判定报告
& $py _w1_withheld_table.py       # LLMRL_WITHHELD_TABLE.md
& $py _w1_declared_vs_withheld.py # 情报口径对照
& $py _w1_seed_view.py            # 逐种子视图
& $py _w1_behavior_signal.py      # 行为侧证据
```

**关键配套文档**：
- `THE_WITHHELD_RESULTS.md` —— 完整结果表（表 A–F）
- `WITHHELD_BRIEFING_EVIDENCE.md` —— 情报口径与硬边界证据台账
- `LLMRL_WITHHELD_TABLE.md` —— 主表生成器输出
